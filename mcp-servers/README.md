# MCP servers for Cosmonic Desktop

Popular [Model Context Protocol](https://modelcontextprotocol.io) servers built as sandboxed WebAssembly components, one directory each, all from [mcp-server-template-rs](https://github.com/cosmonic-labs/mcp-server-template-rs) (rmcp 3.x, MCP 2026-07-28, `wasi:http/handler@0.3.0`). Every server serves a discovery document on `GET /` and `GET /health`, publishes its playbook as a skill at `skill://<name>/SKILL.md`, ships a hermetic e2e suite, takes credentials as secret references, and deploys on Cosmonic Desktop at `http://<name>.localhost:8200/`.

Selection follows [cosmonic/desktop#479](https://github.com/cosmonic/desktop/issues/479) (Reddit and Ahrefs demand). Conventions every server follows: [docs/CONVENTIONS.md](docs/CONVENTIONS.md). Scaffold a new one with `scripts/new-server.sh <name>`; run every suite with `scripts/e2e-all.sh`.

_Status table generated 2026-09-02 from the build and adversarial-review reports; "verified" means an independent reviewer re-ran the gates, the e2e suite and the Desktop ingress checks and found no blocker or major issue._

All deployed servers that need a credential currently run with a **placeholder** secret value (`REPLACE_ME`), so their tools return an actionable "credential not set" error until you replace the value: paste it in Cosmonic Desktop → Settings → Secrets under the ref name in the table, or run `cosmonic_set_secret` with that name, then call the server's `check_auth` tool. Servers that talk to a local app (Obsidian, Docker, Playwright) also need the host-level loopback door (Desktop Settings → Security) opened; see each README.

## Credentials: the three layers

1. **In the servers (here).** `GET /` carries a `credentials` block (ref, env, kind, description, `obtainUrl`, scopes, presence-only status), every authenticated server has a `check_auth` tool with a precise remediation, and READMEs carry vendor deep links (Slack app-from-manifest, Notion integrations page, Atlassian token page). See [CONVENTIONS.md](docs/CONVENTIONS.md#credentials-self-describing-testable-layer-1).
2. **In Desktop, apply time** ([cosmonic/desktop#480](https://github.com/cosmonic/desktop/issues/480)): missing secret refs prompt a paste field instead of a crash loop; a Test button runs `check_auth`.
3. **In Desktop, Connections** ([cosmonic/desktop#481](https://github.com/cosmonic/desktop/issues/481)): an OAuth broker; workloads import `cosmonic:credentials/token` and receive short-lived tokens for the one connection their manifest names.

## Build, test, deploy

```console
$ cd mcp-servers/<name>
$ cargo build --release            # wasm32-wasip2 component
$ ./scripts/e2e.sh                  # hermetic suite under wasmtime 46/47 (48 traps; see CONVENTIONS)
$ claude mcp add --transport http <name> http://<name>.localhost:8200/
```

Deploy with the promote flow in [CONVENTIONS.md](docs/CONVENTIONS.md#deploy-on-cosmonic-desktop-local-build) and apply `deploy/workload.yaml` with the digest-pinned image; `postgres-mcp`'s suite is Desktop-only because wasmtime cannot provide `wasmcloud:postgres`.
